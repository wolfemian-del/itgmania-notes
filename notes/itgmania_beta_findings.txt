7u. VIDEO DECODING REFACTOR e4b4bf0755 (2026-10-04) [CODE unless tagged; no video playback possible here]
  - BASIS: git show/diff e4b4bf0755~1..e4b4bf0755; src/arch/MovieTexture/ at
    beta~1 equals v1.3.0, so the diff IS the v1.3.0 -> beta change. Read in full:
    new MovieTexture_FFMpeg.cpp/.h, all hunks of MovieTexture_Generic.cpp/.h,
    the old FFMpeg code. Checked: g++ -std=c++17 -fsyntax-only -Wall -Wextra on
    both .cpp against extern/ffmpeg-w32/include: exit 0, no warnings in these
    files (not linked). PR thread not looked for [UNVERIFIED].
  - COMMIT: Brandon W, author 2026-09-18, committer 2026-10-03, "Refactor video
    decoding subsystem for performance, sync, and maintainability." No body. 4
    files, +531/-523. Only MovieDecoder_FFMpeg implements MovieDecoder;
    MovieTexture_Null untouched; Lua entry points (RageTexture.cpp ~106-114:
    position/loop/rate) unchanged. No Docs mention.
  1. WHAT CHANGED
  a) Decoder. v1.3.0: sliding window of 50 FrameHolder raw AVFrames (comment
     "roughly 100mb") plus packet_buffer_ growing one PacketHolder per packet
     until EOF then reused for looping (payloads appear to stay resident
     [INFERRED]); per-holder mutexes; the decode thread polled sleep_for(1 ms)
     when full; sws_scale ran in GetFrame on the MAIN thread. Beta: a bounded
     queue. The worker reads, decodes AND colour-converts into a ConvertedFrame;
     kMaxQueueFrames=4 queued, kMaxPoolFrames=6 recycled; it blocks on a
     condition variable when full (no polling). GetFrame on the main thread only
     pops and memcpy's rows into the texture surface (or discards for nullptr).
     Packets are not retained.
  b) Timestamps: PTS = best_effort_timestamp, else pts, else pkt_dts; first
     PTS subtracted; forced monotonic (a backwards PTS becomes last_pts +
     last_duration); duration = pkt_duration, else avg_frame_rate, else 1/30 s.
     v1.3.0 used pkt_dts (or last frame + delay).
  c) Looping: v1.3.0 Rollover() plus an offset_ ring. Beta: the worker loops
     itself. At EOF it marks the last QUEUED frame is_last_frame (or sets
     end_of_movie_ if the queue is empty), then SeekToStart (av_seek_frame,
     avcodec_flush_buffers, PTS reset) and keeps decoding. GetFrame returns 1
     for the flagged frame; the Generic side sets clock_ = 0. Rollover() is a
     no-op.
  d) Display pacing (Generic.cpp): first frame shown at once
     (first_frame_displayed_; SetPosition(0) clears it); frames more than 0.1 s
     late (CheckFrameTime() < -0.1) are popped without upload until the front
     frame is within 0.1 s or the queue is empty (the shown frame can then be up
     to one frame early [INFERRED]); loop wrap sync: if loop_ and the front
     frame's PTS < clock_ - 0.5, clock_ = that PTS; finished_ && loop_ triggers
     Rewind() and restart; SetLooping now also forwards to the decoder (in
     v1.3.0 Lua loop(false) changed only the Generic flag while the decoder kept
     looping; on beta loop(false) lets the decoder thread exit at EOF).
  e) Teardown: ~MovieTexture_Generic calls Cancel(), joins the thread, resets
     the decoder; ~MovieDecoder_FFMpeg calls Cancel()+Close(); Close() frees
     sws/codec/format contexts with the AVIO pb nulled first, deletes the
     RageFile, uses avio_context_free.
  2. SUPPORT FOR THE COMMIT MESSAGE (no measurement): removed 1 ms polling and
     main-thread sws_scale; the main thread now memcpy's pitch x height per
     shown frame [INFERRED: less main-thread work]. Sync: late-frame dropping and
     best_effort_timestamp; no audio clock: clock_ still advances by engine
     delta time x rate_ as in v1.3.0.
  3. DIFFERENCES A PLAYER COULD SEE [INFERRED; not tested]
  a) Look-ahead shrinks from 50 decoded frames to 4: ~133 ms at 30 fps, ~67 ms
     at 60 fps, vs ~1.7 s at 30 fps. A decoder stall longer than that (slow disk,
     CPU contention, heavy keyframes) shows as a held frame, then dropping of
     late frames; likeliest for large videos on slow CPUs.
  b) Memory per open movie (arithmetic only). Surface = image size (not padded
     to a power of two: Generic.cpp ~226-229 [CODE]); ConvertedFrame = pitch x
     height. 1280x720: ~1.8 MB (YUYV 2 B/px) or 3.7 MB (32-bit); 1920x1080: ~4.1
     / 8.3 MB. Up to ~6 live frames = 11-22 MB (720p), 25-50 MB (1080p).
     v1.3.0: 50 raw YUV420 frames (~1.4 MB at 720p, 3.1 MB at 1080p = ~69 /
     155 MB) plus all packets (~the compressed file size).
  c) Decode errors: the worker stops for good on any avcodec_receive_frame error
     other than EAGAIN/EOF: logs "DecodeMovie: decoding error: N", leaves the
     loop, returns 0; failure_ is NOT set, so the picture freezes on the last
     frame. v1.3.0 treated a non-zero receive status as "likely not fatal" and
     continued [CODE for both]. avcodec_send_packet errors only log a warning.
     Whether real files hit receive_frame errors is [UNVERIFIED].
  d) Lower CPU when the queue is full (no polling) [CODE].
  4. OBSERVATIONS (not confirmed defects)
  a) STALE end_of_movie_ WHEN LOOPING [CODE for the lines; MODEL for the
     effect]. DecodeMovie EOF branch (~415-433): if the queue is EMPTY at EOF it
     sets end_of_movie_=true; with looping_ it then seeks and continues, and
     nothing clears the flag (writes: Init ~159, HandleReset ~236, both EOF
     branches). EndOfMovie() = end_of_movie_ && queue empty. UpdateFrame treats
     EndOfMovie() like a last frame and, when loop_, sets clock_=0. So after
     such an EOF, each time the queue is momentarily empty the clock resets to 0
     while the next PTS is later, and display waits for the clock to catch up
     (the wrap-sync handles only frames EARLIER than the clock). The flag is set
     only when decoding is not staying ahead of display at the loop point
     (normally the queue holds up to 4 frames at EOF and the flagged-frame path
     is used).
     MODEL: a 60-line time-stepped Python transcription (not the real class; not
     saved). 30 fps, 60-frame loop, 12 s, consumer at 60 Hz: decode 2 ms/frame:
     6 loops, 6 clock resets, flag False. Decode 40 ms/frame (slower than real
     time): flag stuck True, 14 clock resets for 2-4 loops (~8 spurious). Decode
     30 ms: same as 2 ms. With the flag also cleared on seek: 0 resets. A
     candidate one-line change: set end_of_movie_ only when !looping_ (not
     applied; not tested on the real class). The model fixes the rates; real-world
     likelihood UNKNOWN.
  b) LOST WAKE-UP WINDOW [INFERRED from C++ condition_variable rules]: Cancel()
     and Rewind() set atomics WITHOUT queue_mutex_ then notify_all; a notify
     between the worker's predicate check and its block is lost. For Cancel() the
     main thread then waits in join() with nobody to notify: a hang on destroying
     a movie texture. Tiny window, only while the queue is full; not observed.
  c) can_consume_cv_ is notified in four places and never waited on.
  d) last_pts_, last_duration_, timestamp_offset_, first_pts_seen_ are written
     by the worker without queue_mutex_; GetTimestamp reads last_pts_ under the
     lock only when the queue is empty. Formally a data race; small practical
     effect [INFERRED].
  e) Restart after the thread exited: with loop(false) the worker exits at EOF
     (or after a decode error, 3c). Rewind() only sets reset_, serviced only by
     the worker, so Rewind/position(0) cannot restart it; SetPosition does not
     clear finished_. Same reading for v1.3.0 (UpdateFrame returned early when
     finished_), so no regression seen; callers: Lua RageTexture:position(),
     Sprite.cpp ~854, ActorMultiVertex.cpp ~374. The new finished_&&loop_
     restart branch has the same limit if loop is turned on after the thread
     ended [INFERRED].
  f) GetFrame copies rows into the texture surface; with
     MovieTextureDirectUpdates (default true, Generic.cpp ~32) the surface
     pointer is locked texture memory (~230-234). Behaviour with the other
     setting not read [UNVERIFIED].
  5. COMPATIBILITY: new code reads AVFrame::pkt_duration and
     best_effort_timestamp, present in the pinned FFmpeg: extern/ffmpeg commit
