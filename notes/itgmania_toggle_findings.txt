7f. PACK / SONG TOGGLE IDEA (2026-09-30, v1.3.0 8a3bf8884a)
  [CODE unless noted; TESTED = user-run.] Design and patch details live in
  itgmania_pack_toggle_sketch.txt (Parts A-H); this entry keeps the facts
  found while framing the idea.
  Idea (user): let players toggle packs and/or songs so they truly do not
  appear (manageable menus, large libraries, performance).
  Underscore myth: a leading "_" does NOT hide a pack [CODE: only
  StripMacResourceForks (names starting "._") and StripCvsAndSvn (names ending
  CVS, .svn, .hg) filter folders in LoadSongDir]. TESTED: "_Pack" loads
  normally (sorts last, SongUtil::MakeSortString); "._Pack" disappears, only
  as a side effect of the macOS filter; it drops the folder before any song
  loading, so it should save load time [INFERRED; library too small to
  measure].
  Crash/empty-data worry: not found in ITGmania. No persistent pack database;
  the cache is keyed by path (SongCacheIndex.cpp header comment), so a renamed
  folder is a new path. Pruning of orphaned cache files not found
  [UNVERIFIED]. Worry probably from StepMania 5 / Project Outfox; dropped.
  Existing per-song disable:
    - Song::m_bEnabled -> UnlockManager::SongIsLocked returns LOCKED_DISABLED
      -> MusicWheel drops it in BuildWheelItemDatas (~505) and
      FilterWheelItemDatas (~1341). Persisted in pref "DisabledSongs"
      (g_sDisabledSongs; SaveEnabledSongsToPref / LoadEnabledSongsFromPref).
      TESTED: a DisabledSongs entry hides the song.
    - SYNTAX [CODE: SongManager.cpp split/join on ";"; SongUtil.cpp SongID;
      GetSongFromDir]: ONE preference line, entries separated by ";", each the
      song folder path, e.g.
        DisabledSongs=Songs/PackA/SongOne/;Songs/PackA/SongTwo/
      Matching is lenient: case-insensitive, "\" = "/", trailing and leading
      "/" optional; entries matching no loaded song are ignored; a folder name
      containing ";" cannot be listed. Edit Preferences.ini with the game
      CLOSED (it is rewritten on exit). SaveEnabledSongsToPref rewrites the
      value from loaded songs (drops unloaded ones) and is called only from
      the toggle screen.
    - REPEATED KEYS: TESTED 2026-09-30: with several DisabledSongs lines only
      the FIRST took effect and the others were deleted. The code says the
      LAST should win (7l). UNRESOLVED; use the single-line form.
    - UI: ScreenOptionsToggleSongs (groups) and ...SubPage (songs, On/Off)
      exist in src and save on each change, but nothing reaches them: no
      reference in _fallback or Simply Love dd06138, and they cannot be opened
      as-is because ScreenManager::MakeNewScreen needs a [<Screen>] Class
      metric (sketch A9). Only doc mention: Changelog_sm-ssc.txt ~198-201.
    - Lua: Song:IsEnabled() only (no SetEnabled at v1.3.0). No pack-level
      disable. #SELECTABLE:NO hides a song only with pref HiddenSongs on.
  Limits [INFERRED from call order]: LoadEnabledSongsFromPref runs in
    InitSongsFromDisk AFTER LoadSongDir (~280), so disabled songs are still
    parsed/cache-loaded and keep resident chart, timing and banner-cache
    data: hides rows only, no startup or memory saving. TESTED: listing every
    song of one pack in one DisabledSongs line hides the whole pack row.
  Options evaluated: A engine (hide via DisabledGroups + skip in LoadSongDir;
    best = both; reload via Reload(false) = FreeSongs + full InitAll, see
    sketch A1), B Simply Love only (needs engine Lua setters), C standalone
    tool editing DisabledSongs or renaming to "._" (no live toggle, cache
    invalidated). Recommendation: A, with B as the UI layer.

  - ADJUST SYNC TARGET TIMING (ScreenEdit.cpp ~5626-5642): decided by
    GAMESTATE->m_bIsUsingStepTiming (editor timing mode), not by whether the
    chart has own timing. Mode true + chart has no own timing -> song timing is
    COPIED into the chart and the result applied there (chart becomes
    split-timing; song timing unchanged). Mode false -> song timing. The mode
    starts true only if the chart already has own timing; reset to true on

    ~196-204, XmlFile.h XAttrs = std::map, PrefsManager.cpp ReadPrefsFromFile
    ~462): a repeated key within one section overwrites the earlier value, so
    the LAST line wins; key names case-sensitive; repeated section names merge;
    lines starting ';', '#', '//' or '--' are comments; a line without '='
    only logs a warning.
    DISCREPANCY with the user's test (first line won): possible reasons
    [INFERRED, none confirmed]: lines not in the remembered order; a

    Defaults.ini, before Static.ini); Static.ini or Defaults.ini also sets it.

7m. SL SONG-SEARCH KEYBOARD SHORTCUT (2026-10-02) - sl_song_search_shortcut.patch
  Question: add a keyboard shortcut (user suggested Ctrl+F) on Simply Love's
  song select for the song search, otherwise reached via SortMenu >
  "WhereforeArtThou". Bases: engine v1.3.0 and beta (ScreenSelectMusic.cpp
  diff = DetectCodes only), Simply Love dd06138. Not run by me. [CODE unless
  noted]
  - CTRL+LETTER IS TAKEN BY THE ENGINE (ScreenSelectMusic.cpp ~494-540):
    Ctrl+A..Z jumps to that letter, sets sort to Title (Artist stays Artist),
    writes m_PreferredSortOrder, then ChangeSort/SetOpenSection/SelectSection.
    Ctrl+Shift+R reloads the selected song (checked first); Ctrl+Backspace
    deletes a song when AllowSongDeletion.
  - ORDER: ScreenManager::Input (~562-565) calls the top screen's Input, THEN
    PassInputToLua, regardless of the return value, so a Lua callback cannot
    pre-empt the engine handler. set_input_redirected is per PlayerNumber and
    PlayerNumber is filled only for keys mapped to a game button
    (StepMania.cpp ~1360), so it cannot suppress the engine for an unmapped
    key [INFERRED: an unmapped key arrives with nil PlayerNumber; SL's own
    handlers rely on it].
  - TESTED by user: Ctrl+F and Ctrl+Shift+F both jump to F and switch to
    Title; the Title sort persists after visiting the song-select settings
    menu; Alt+F and plain F do nothing.
  - PLAIN F IS FREE: no engine file except input drivers and the key enum
    references KEY_Cf; GameManager.cpp keyboard auto-maps use q,w,e,r,t,y,u,i,
    a,d,s,x,z,c; debug overlay letters stop at Q-P, A, S, D; SL has no
    DeviceButton_f binding. A player can still map F in the key mapping screen.
  - HOW THE PATCH WORKS (3 files: new SongSearch/ShortcutHandler.lua, one
    LoadActor line in ScreenSelectMusic overlay/default.lua, en.ini text for
    KeyboardFeatures): an input callback added in OnCommand only if theme pref
    KeyboardFeatures is on. On FirstPress of DeviceButton_f it queues SortMenu's
    existing DirectInputToEngineForSongSearch command. Guards: no modifier held
    (tracked from events; no Lua key-state API); event PlayerNumber nil; no
    player input redirected (every overlay redirects); top screen is
    ScreenSelectMusic; not transitioning; not course mode; wheel not locked.
    Calls wheel:Move(0) first (the key release goes to the text entry)
    [INFERRED]. Checked here: Lua syntax, a mock-based logic test in embedded
    Lua 5.4, git apply --check on a fresh dd06138. NOT run in the game.
  - Typing "f" in the box does not re-trigger (only ScreenTextEntry gets input;
    it types on FirstPress, so the opening F is not typed) [INFERRED].
  - LIMITS [INFERRED]: modifier state comes from events this callback saw; a
    stale flag ignores F until that modifier is pressed and released once.
    Ctrl held before load plus F would run the engine jump and the search.
    Key identified by position code; non-US layouts UNVERIFIED. Only
    ScreenSelectMusic (the Casual screen is not touched).
  - OBSERVATION: SortMenu/default.lua loads SongSearch/SongSearchSettings.lua
    (line 16) then defines a second local SongSearchSettings (~line 60) that
    shadows it, so edits to the file would not change the sort-menu search.
  - Engine alternatives not done: (a) opt-out of Ctrl+letter jump (needs an
    engine change; SL pins an engine commit); (b) Lua undoing the jump.
  - USER CHECKS (KeyboardFeatures on): F on song select opens the box and
    stops a held wheel direction; type, OK: results; Back: closes. F with sort
    menu / results / test input open: nothing. Ctrl+F still jumps, no box.
