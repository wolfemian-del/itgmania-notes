PART A. FACTS FROM THE CODE THAT CONSTRAIN THE DESIGN
-----------------------------------------------------
A1. A full reload path that REMOVES songs already exists [CODE:
    SongManager.cpp Reload ~175-255]. Reload(bAllowFastLoad, ld): flush
    dir caches, save machine + player profiles, unjoin players, FreeCourses,
    FreeSongs, then InitAll(ld, onlyAdditions=false), reload profiles,
    rejoin, UNLOCKMAN->Reload(), UpdatePreferredSort. So a "skip" toggle
    can take effect through a reload WITHOUT restarting the game. Earlier
    note said the removal path was unread; it is FreeSongs + InitAll.
    Callers: ScreenReloadSongs.cpp:80 and ScreenInstallOverlay.cpp:171,
    both with bAllowFastLoad=false, i.e. PREFSMAN FastLoad is forced
    OFF for that reload. CORRECTED 2026-10-01: FastLoad off does NOT mean
    re-parse everything. Song::LoadFromSongDir (Song.cpp ~311-316) still
    uses an existing cache file unless GetHashForDirectory(songdir) !=
    the stored hash. That hash = per-file (mtime + size) from the file DB,
    no file contents read (RageUtil_FileDB.cpp FileSet::GetFileHash;
    RageFileDriverDirectHelpers.cpp hash = st_mtime). So unchanged songs
    load from cache after a stat pass; only new/changed/uncached songs
    are fully parsed (and re-cached). ImageCache.cpp ~415 same pattern
    (full-file hash of images when FastLoad is off). [CODE] Per-song cost
    versus a FastLoad startup: not measured [UNVERIFIED]. Time it in game:
    "Reload Songs" vs normal startup.
A2. LoadSongDir structure [CODE: SongManager.cpp ~415-700]:
    1 list pack folders; 2 StripCvsAndSvn/StripMacResourceForks;
    3 per pack SanityCheckGroupDir + list song folders -> into
    std::map mapGroupSongDirs (keyed by pack folder name); 4 build
    songsToLoad from the map (and create Group objects here, ~520-525);
    5 threaded load; 6 finalize loop over the map (AddGroup, banner
    cache, LoadGroupSymLinks). A pack name absent from the map is never
    listed, never given a Group, never loaded, never cached-read.
    The right filter point is step 3 (next to SanityCheckGroupDir) or
    just before step 4.
A3. Zero-song packs are already handled: a group whose songs all fail or
    are absent gets its Group deleted and is not added (~640-650); note
    the `continue` there skips LoadGroupSymLinks for it. [CODE]
A4. FreeSongs clears songs, groups, series map, m_SongsByDir and
    m_mapSongGroupIndex [CODE: SongManager.cpp ~770-797], so Reload fully
    rebuilds everything, including Series (AddGroup re-runs).
A5. The group list used by menus comes from m_sSongGroupNames, filled by
    AddGroup only for packs that loaded at least one song
    [CODE: GetSongGroupNames ~874; AddGroup ~313]. CONSEQUENCE for design:
    if a disabled pack is SKIPPED at load, it never appears in
    ScreenOptionsToggleSongs (which lists GetSongGroupNames), so the UI

A6. Scores: the profile loader deliberately tolerates song IDs with no

    So skipping a pack should not delete its scores; they stay in the
    profile and reattach when the pack loads again. [INFERRED for the

A7. .include "symlink" files inside a pack load their destination song

PART B. DESIGN OPTIONS (evaluation; none implemented)
-----------------------------------------------------
Goals: (1) menus show only wanted packs/songs, (2) optionally avoid the
load cost, (3) toggle from inside the game, (4) settings persist,
(5) scores and cache are not damaged.

B1. HIDE ONLY (live toggle, no load saving)
  - State: Group gets a bool m_bEnabled (default true). Persisted in a new
    preference "DisabledGroups" (";"-separated pack FOLDER names, same
    style and lenient matching as DisabledSongs).
  - Effect: UnlockManager::SongIsLocked returns LOCKED_DISABLED when the
    song's group is disabled. Because every wheel, criteria and random
    path already keys on LOCKED_DISABLED (A12), no wheel change is needed.
    A separate group flag keeps individual song toggles intact when a
    pack is switched off and on again (a pack switch must not overwrite
    per-song state).
  - Cost: one group lookup per SongIsLocked call (map find by name; the
    wheel calls it per song per build/filter). [INFERRED: negligible vs
    the existing work; not measured]
  - Series/wheel: a pack with all songs hidden has no rows (user-tested
    equivalent with DisabledSongs), so series counts and parent rows
    follow. On beta the single-pack-series rule counts groups REGISTERED,
    not visible ones (series notes 12a), so hiding one of two packs in a
    series leaves a parent row with one visible child. [INFERRED]
  - Does not save startup time or memory (A1/A2: load happens first).

B2. SKIP AT LOAD (saves time and memory; needs reload/restart)
  - In LoadSongDir step 3 (A2), after SanityCheckGroupDir, skip pack
    folder names present in DisabledGroups before adding to
    mapGroupSongDirs. Nothing else in the load path sees the pack.
  - Takes effect on next startup or on Reload(false) (A1), which is the
    full service-menu "Reload Songs"; Simply Love's "Load New Songs"
    uses LoadAdditions and will NOT remove loaded packs (A11) but WOULD
    add a pack that was un-skipped. [CODE]
  - Reload(false) forces FastLoad off, so each song's cache is validated
    by a directory hash (mtime+size) first; unchanged songs still load
    from cache (A1, corrected 2026-10-01). [CODE; relative speed vs a
    FastLoad startup not measured]
  - UI problem (A5): skipped packs are not in GetSongGroupNames, so the
    toggle screen must list packs from the disk directory listing (or
    from DisabledGroups plus loaded groups) to allow re-enabling.
  - Scores stay in the profile (A6). Cache files for the skipped pack
    stay on disk, unread. [INFERRED]

B3. RECOMMENDED: B1 + B2 TOGETHER
  - One list (DisabledGroups) drives both. A pack toggled off in the UI
    is hidden immediately (B1), and is not loaded the next time songs are
    loaded (B2). Toggling ON needs a reload before songs appear, since
    they were never loaded; UI text should say so. Alternative: keep B1
    only unless a large library demands B2.
  - Keep DisabledSongs as is (song level).

B4. UI LAYERS
  a) Engine screens only: add LineToggleSongs to [ScreenOptionsService]
     and define the two missing screen sections (A9/A10). Pack-level rows
     would need ScreenOptionsToggleSongs changed to add On/Off per pack
     (today it is a plain list that opens the song page).
  b) Simply Love: needs Lua bindings (Part C, C4). SL could add a sort
     menu entry or an operator-menu screen; the sort menu and options
     are Lua (A11). SL pins the engine by submodule-style commit, so
     a theme change needs the engine change first.
  c) Standalone tool: edits Preferences.ini (DisabledSongs/DisabledGroups)
     with the game closed; no engine change needed for song level; pack
     level needs either B1/B2 code or the "._" rename (user-tested:
     "._Pack" hides a pack, by side effect of the macOS filter). [CODE]

    entries for songs not loaded (by design), so per-song disables inside a
    skipped pack are lost if the song toggle screen saves while the pack is
    skipped. Options: merge old entries into the saved value, or accept the loss.
C5. Interactions and risks (observations):
    - Series: skipped packs behave like zero-song packs; hidden-but-loaded packs

    - Scores persist for unloaded songs (A6) [INFERRED; test: disable a pack,

    - Last-played song and courses: resolved in H3.
    - Preferences.ini is rewritten from the loaded preference registry on save;

    - Beta: both engine patches apply cleanly (H1).
    - Contribution: GitHub PRs against beta; keep the engine patch small (C1-C3
